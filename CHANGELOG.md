# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

- Fix CI so each pull request check has its own name and reports its own result: Go formatting, Go vet, Go tests, Go build, Swift tests, Mac app build and Changelog entry. A red check names the failing file and line where there is one and the command to run it yourself, a change that adds no line under `## [Unreleased]` fails Changelog entry (unless labelled `no changelog`), and Go formatting now also fails on a Go file that does not parse instead of passing it.
- Fix readings going missing: the relay now times each fetch from the latest reading's own timestamp, so it lands just after LibreLinkUp publishes the next one instead of drifting across it and reading the same value twice. Every reading the source publishes is stored, at about one request a minute.
- Keep the engine's log in the system log under subsystem com.yaanfpv.cgmrelay, category engine, so a Mac app install records what the relay did; the engine also logs once when no new reading has arrived for five minutes, saying whether fetches are failing or LibreLinkUp has nothing newer, and once when readings resume, with how long the gap was.
- Add release tooling for maintainers: `macos/scripts/release.sh X.Y.Z BUILD` builds, signs, notarizes and describes a release (a notarized DMG, a signed `appcast.xml` and the notes taken from this changelog's section for that version), `macos/scripts/publish-release.sh X.Y.Z` is the separate step that tags and publishes it after you type the version, and `macos/scripts/verify-release.sh` checks a published release from the outside.
- Give the Debug build of the Mac app its own identity and default ports (com.yaanfpv.cgmrelay.debug, 1347 and 127.0.0.1:1348), so a development run no longer fights an installed copy for its listener, caches, update state or permissions. Release builds keep their identifier and ports, and a port you have saved is used as is in both.
- Fix xDrip4iOS showing "Fetch error" for a healthy relay: `/api/v1/status.json` now answers without a credential, carrying only the fields it already reported (the relay is up, its clock and its unit), and the address a follower app opens when you tap the status now shows a short plain page naming CGM Relay instead of a 404. Every other endpoint still needs the access token.
- Add in-app updates to the Mac app: CGM Relay checks GitHub once a day and downloads a newer version quietly, and never opens a window or takes focus on its own. A small dot joins the menu bar mark while an update waits, and the panel and right-click menu offer Update Available or Restart to Update. An update installs the next time CGM Relay quits, after its relay has stopped cleanly. Settings gains an Updates pane (check and install automatically, Check Now, last checked, What's New), About is now the app's own page with What's New and Check for Updates, and the app menu's About CGM Relay opens it. A build that carries no release key starts no updater and says so.
- Fix CI building the Mac app with an older SDK than the one it ships with: the app job now runs on the Xcode 27 runner image and prints the toolchain it used.
- Add a way to connect a phone app without typing the token: the Connect pane now has a follower app picker (xDrip4iOS, xDrip+, LoopFollow, Nightguard), remembered between visits. xDrip+ and LoopFollow get a QR code that imports the Nightscout settings straight into the app, shown only after the token is shown. xDrip4iOS and Nightguard get a QR code that opens a page served by the relay itself, from a code that lasts ten minutes and never contains the token, with each value and its own Copy button.
- Fix the token row so Show, Hide and Copy keep their size and labels when the token is shown; the token wraps beside them instead of squeezing them into empty ovals.
- Fix the relay refusing a correct token that picked up a trailing space, tab or line break while being copied: whitespace around the `token` query value and the `api-secret` header is now ignored, and a wrong token still fails.
- Fix the in-app steps for xDrip4iOS to name where its fields are (Settings, Sharing and Services, Nightscout), to give the address without its port beside a separate Port, and to leave API_SECRET blank.
- Fix Open at Login on a fresh install: setup and General offered no way to turn it on and said this build can't open at login. It now reads as off with Turn On available, and only says it is unavailable, with the system's own reason, if the system refuses to register it.
- Fix setup's first step: Email and Password use their labels as placeholders, one button (Sign In, then Continue) sits in the footer, Return in the password field signs in, and Sign Out sits in the account's own row, in setup and in Settings.
- Fix the Alerts pane: Open System Settings opens CGM Relay's own Notifications page, the notice shows only when macOS really has notifications turned off for CGM Relay, and its text and button have room.
- Fix the right-click menu so no item carries an icon.
- Fix quitting from the Dock while Settings or setup is open: it now closes the windows and leaves CGM Relay running in the menu bar. Every Quit inside the app (the app menu, Command-Q, the panel, the right-click menu), and logging out, restarting or shutting down, still quit it, and each now waits for the engine to stop first, so opening the app again never says it is already running.
- Fix the menu bar icon's drop, which read as tall and stretched: it is now a rounder drop, a circular body under a short, softly rounded point.
- Add a calm menu bar icon: it follows the menu bar's own light, dark and tinted look while readings are current, turns amber when a reading is late and red when CGM Relay is stopped or sign-in is failing, and says its state in words to VoiceOver. A new General setting, off by default, shows the latest reading and its trend arrow beside the icon while readings are current.
- Add a right-click menu on the menu bar icon with Settings…, Report a Bug… and Quit CGM Relay, and Report a Bug and Suggest a Feature buttons in About that open the matching GitHub issue form (bug reports and feature requests each have their own) with the app version, build, macOS version and chip already filled in.
- Fix the menu bar icon so its panel opens from the keyboard and from VoiceOver, not only from a mouse click.
- Add a fourth setup step to the menu bar app that offers Open at Login (nothing is registered until you click it, and it shows when System Settings needs to approve it) and says where your readings are stored and that CGM Relay now lives in the menu bar. The account, Tailscale and Tailscale HTTPS checks in setup now read as rows with a fixed status slot, so nothing moves when a state changes.
- Add first-launch setup to the menu bar app: until it is finished, every launch opens a setup window (sign in, reach your phone, connect your app with the address, token, QR code and the field names xDrip4iOS and xDrip+ use); setup finishes once a phone can actually reach this Mac, and until then the reach step waits. Set Up Later closes setup for now without finishing it, so it reopens on every launch, and from the menu's "Finish setup…", until a phone can reach this Mac. With Tailscale running, setup can turn on Tailscale HTTPS for you by running one command it shows you first, after checking that its port has no entry in your Tailscale settings; Advanced shows what Tailscale itself reports and turns it off again after a confirmation, by running the matching command once it has checked that the entry there is this Mac's own.
- Fix the Nightscout API answering 404 to `/api/v1/treatments`, `/api/v1/devicestatus` and `/api/v1/profiles.json`, which Nightguard, xDrip+, xDrip4iOS and LoopFollow request: each now gets the same empty answer as its `.json` or singular sibling, behind the same credential check.
- Add CGM Relay's own app icon, so the Dock and Finder show it instead of a generic blank tile.
- Fix CI so it stops warning about deprecated Node runtimes: `checkout` and `setup-go` are now pinned to their current releases, both running on Node 24.
- Compress a large Nightscout API response with gzip when the requesting app asks for it, so a follower catching up on hours of history downloads far fewer bytes over a slow connection; a small response, or a request that never asks for gzip, is written exactly as before.
- Fix the local status endpoint's follower-client list so it can no longer grow without bound: it now keeps the 256 most recently seen clients and drops the longest-silent one to make room for a new one.
- Add the reading model, source interface, and an encrypted SQLite store for glucose readings.
- Add a LibreLinkUp source that signs in, follows region redirects, and refreshes an expired session automatically.
- Add the minute-by-minute poller that fetches readings, fills history gaps, backs off on rate limits and auth failures, and prunes old readings on start and once a day.
- Add a Nightscout-compatible API handler so follower apps like xDrip4iOS can poll the relay for entries, status, and current readings.
- Add a `setup` command that writes a config file and encryption key, with environment variable overrides for Docker.
- Add a `serve` command that signs in, polls, and serves the Nightscout API together, with `status.json` fields xDrip4iOS, LoopFollow, and Nightguard each need to accept the site.
- Add a loopback-only local status endpoint reporting poller health and which follower clients are actually polling, for the menu bar app and headless installs alike.
- Add `serve --config-stdin`, which reads the whole configuration as one JSON object on stdin instead of the config file or environment, so a caller holding secrets in a keychain never has to write them to disk or the process environment. The relay then runs until stdin closes, so it never outlives the caller.
- Fix the Nightscout API to accept every credential form and connection probe that xDrip4iOS, xDrip+, LoopFollow, and Nightguard actually send: a path the relay does not implement now answers 404 before any credential check, and an `api-secret` header carrying the raw access token (not only its SHA-1 hash) is now accepted.
- Add the macOS menu bar app: a status dot, current reading, and follower activity read from the engine's status endpoint, with the engine supervised as a child process and restarted with backoff if it stops unexpectedly.
- Add a standalone runnable fake LibreLinkUp server (`go run ./cmd/llufake`) and an optional `librelinkup_base_url` configuration field, so the engine and the menu bar app can be driven through every status state without a real account.
- Fix the menu bar app so a saved reading database this Mac's key can no longer open (after a Keychain reset, a restored backup, or a move to a new Mac) is recognised instead of restarted forever: the menu now explains what happened and offers a "Start Fresh…" recovery that moves the old file aside, never deleting it.
- Fix two copies of the menu bar app opened at once so only one of them ever uses the saved readings: the other says so plainly and offers to try again the moment the first one quits, instead of restarting forever. Fix a saved reading database that cannot be read at all, not just one sealed with the wrong key, to get the same "Start Fresh…" recovery instead of restarting forever. Fix the menu so stopping the engine keeps showing the last reading it saw, instead of claiming there had never been one.
- Fix the menu bar app so the engine it starts gets an explicit, minimal set of environment variables instead of this app's own whole environment: nothing the engine needs ever arrives that way, since its configuration is exactly what the app writes to its standard input.
- Fix a development build of the menu bar app so a launch given no development Keychain service argument uses a fixed development service and its own database folder, instead of the real Keychain item and the real reading database.
- Add the Settings window: sign in and out of a LibreLinkUp account, checked against LibreLinkUp before anything is saved (`cgm-relay check-account`); a Connect pane showing the follower address, token, and a QR code, with a way to rotate the token; General, Advanced, and About panes for login-at-startup, units, retention, port, and who can reach the relay (this Mac, a Tailscale tailnet, or the local network); and two optional notifications, for no new reading in a while and for sign-in failing.
